# Design Traceability Matrix

| Pillar | Mechanic | Scene/slice | State variable | UI surface | Test | Acceptance |
|---|---|---|---|---|---|---|
| Liberate under pressure | quiet extraction vs public disruption | VS-OSTIA-001 | trust, supplies, exposure, retaliation | commitment preview, debrief | VS-CHOICE-001 | two viable approaches; asymmetric consequences visible |
| Read systems | verify testimony and ledger | VS-OSTIA-001 | information, evidence status | evidence panel | VS-EVIDENCE-001 | 80% explain why testimony is partial/corroborated |
| Build trust | negotiate and listen | Act I/VS-OSTIA-001 | trust, cohesion, relationship | speaker/status panel | VS-REL-001 | affected person can refuse or alter plan |
| Choose the cost | allocate shelter, route, supplies | VS-OSTIA-001 | supplies, nodes, links | network state screen | VS-LOGISTICS-001 | immediate opportunity cost is legible |
| Escape and rebuild | changing route and recovery state | VS-OSTIA-001 | organization, retaliation, cell status | route/debrief screen | VS-ESCAPE-001 | failure changes state without pure reset |
| Historical integrity | codex classification | slice and every main mission | FACT/RECONSTRUCTION/FICTION/OPEN QUESTION | codex metadata | HIST-001 | no claim lacks label/source/review status |
| Accessibility | remap, subtitles, visual audio, reduced effects | every slice beat | settings schema | accessibility menu/HUD | ACC-001 | mandatory matrix green on target platform |
| Technical reliability | deterministic state and save | slice and CI | seed, state hash, save version | recovery UI | TECH-001 | fixed input reproduces identical hash; interrupted save recovers |

## Coverage rule

No feature is canonical until it appears in this matrix or is explicitly marked supporting/aspirational.
