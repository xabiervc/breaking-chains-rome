# Implementation Handoff

## Entry criteria

- Use `docs/DESIGN_AUTHORITY.md` as the normative source.
- Use `docs/IMPLEMENTATION_DECISION_REGISTER.md` for closed decisions and prototype hypotheses.
- Build only the mandatory content in `docs/CONTENT_SCOPE_MATRIX.md`.
- Implement `VS-OSTIA-001` from `docs/VERTICAL_SLICE_OPERATIONAL_SPEC.md`.
- Track every result in `docs/REQUIREMENT_STATUS_MATRIX.md`.

## First implementation order

1. Data contracts and stable IDs.
2. Network state and deterministic mutation rules.
3. Evidence/choice state and consequence debrief.
4. Save schema and recovery path.
5. Greybox route, shelter, warehouse, and dock spaces.
6. Player interaction, two approaches, and fail-forward.
7. Accessibility settings and visual/audio redundancy.
8. Placeholder dialogue, codex classifications, and localization IDs.
9. Art/audio pass sufficient to test identity and readability.
10. Automated tests, replay hash, metrics capture, and playtest build.

## Exit criteria

The handoff is complete when the slice has a reproducible build, two viable approaches, visible state changes, one non-protagonist override, save/recovery, mandatory accessibility controls, deterministic replay, and attached playtest/performance evidence.
