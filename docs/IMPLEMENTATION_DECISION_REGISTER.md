## Prototype hypotheses

| ID | Hypothesis | Validation experiment | Pass signal |
|---|---|---|---|
| HYP-001 | Players understand the quiet/public tradeoff before committing | moderated slice playtest | >=80% explain one tradeoff |
| HYP-002 | Network variables are readable without turning history into a dashboard | UI task test | >=80% identify one changed relationship/resource/pressure |
| HYP-003 | Fail-forward is more motivating than pure reload | compare recovery and reload builds | majority prefer/understand meaningful recovery |
| HYP-004 | The slice supports 20–35 minutes without padding | timed playtest | median completion in target range; no redundant segment |
| HYP-005 | The historical context changes decisions rather than only dialogue | blind comparison of systems-on vs systems-off slice | players make materially different plans |

## Accepted risks

- Exact balance is intentionally deferred to prototyping.
- Final control feel, emotional impact, and performance are not document-verifiable.
- Ancient-language pronunciation remains specialist-dependent.
- Full ten-region breadth is not required for the first slice.

These are acceptable only because they have validation gates and do not change the defined identity or core loop.
